# 鉄人サイトの更新方法

**下のリンクを開き、内容を書き換えて保存してください。数分後にサイトへ反映されます。**
最初にGitHubへログインしてください。

## 1．変更したいものを開く

- [お知らせを書き換える](https://github.com/tetsujinkujira/tetsujin-bento/edit/main/更新データ/お知らせ.txt)
- [日替わりを書き換える](https://github.com/tetsujinkujira/tetsujin-bento/edit/main/更新データ/日替わり.txt)
- [価格を書き換える](https://github.com/tetsujinkujira/tetsujin-bento/edit/main/更新データ/商品価格.txt)

リンクを押すと、そのファイルの編集画面が開きます。

## 2．必要なところを書き換える

### お知らせ

日付・件名・本文を、新しい内容に書き換えます。
「日付：」「件名：」「本文：」の文字は残してください。

```text
日付：2026-11-01
件名：11月の日替わりメニューを更新しました
本文：
いつもご利用ありがとうございます。
11月の日替わりメニューをご覧ください。
```

日付は「2026-11-01」の形で書きます。本文は「本文：」の下に書きます。
以前のお知らせは新しい内容に置き換わります。

### 日替わり

最初の「年」と「月」を書き換えます。

```text
年：2026
月：11
```

次に、それぞれの曜日の料理名を書き換えます。料理は1行に1つ書きます。

```text
【月曜日】
鶏の唐揚げ
ポテトサラダ
```

料理が未定の日は、料理名の代わりに次のように書きます。

```text
【土曜日】
備考：当日、お電話にてご確認ください。
```

**「【月曜日】」から「【土曜日】」までの見出しは消さないでください。**
「商品名」「よみがな」はそのまま残します。
日替わりの価格を変えるときは、価格ファイルの「桜桃」を変更します。

### 価格

変更したい商品を探し、「：」の右の数字だけを書き換えます。

例：桜桃を700円から750円に変更する場合

変更前：

```text
桜桃：700
```

変更後：

```text
桜桃：750
```

**商品名と「：」は消さないでください。価格にカンマや「円」は不要です。**
変更しない商品の行は、そのまま残してください。
大盛り料金は「ライス大盛り」の数字を変更します。

## 3．保存する

1. 入力した日付・料理・金額を確認します。
2. 画面右上の緑の **「Commit changes…」** を押します。
3. 表示された入力欄に、変更内容を書きます。例：「11月の日替わりを更新」
4. **「Commit directly to the main branch」** を選びます。
5. 緑の **「Commit changes」** を押します。これで保存完了です。

※ mainへ直接保存する選択肢が出ない、または保存できない場合は、画面の内容を管理者・技術担当者に伝えてください。

別のファイルも変える場合は、手順1から繰り返します。ファイルを保存するたびに公開処理が始まります。

## 4．サイトを確認する

1. [公開処理の画面を開きます](https://github.com/tetsujinkujira/tetsujin-bento/actions/workflows/deploy.yml)。
2. 一番上にある、自分が保存した変更の行を見ます。黄色は処理中です。**緑のチェックになるまで待ちます。** 通常は数分程度です。
3. [鉄人のサイトを開きます](https://www.tetsujin-kujira.com/)。
4. 自分が変えたお知らせ・日替わり・価格を確認します。公開後、閲覧中の画面も60秒ごとに最新情報を確認して自動で更新します。別のタブから戻った時にも確認します。通信できない場合は画面に案内が出ます。

**サイトに変更内容が表示されたら、作業完了です。**

## 赤い「×」が出たら

更新は公開されず、以前のサイトが残ります。

1. 赤い「×」の行を開きます。
2. 「build-and-test」→「Build」を開きます。
3. 「日替わり.txt」「商品価格.txt」などが書かれた日本語のエラーを読みます。
4. 手順1のリンクから該当ファイルを開き、直して保存します。

例：「【土曜日】がありません」なら、消した「【土曜日】」を戻します。

**直し方がわからなければ、失敗した画面のURLを技術担当者へ送ってください。**

## 覚えておくこと

- 編集するのは上の3ファイルです。JSONを編集する必要はありません。
- 「750」を「7500」と書いた場合など、数字の内容までは自動で判断できません。保存前に確認してください。
- 商品の追加・削除・改名や写真の変更は、技術担当者に依頼してください。
- この更新の仕組みに追加利用料はかかりません。既存のセキュリティ監視も継続します。
- 自動更新機能の導入前から開いたままの画面は、最初の一度だけ再読み込みしてください。以後の内容更新は自動で反映されます。

手元のファイルで更新している方は、mainの最新版にある「更新データ」フォルダの3ファイルを編集し、これまでと同じ方法で保存・送信してください。

## 管理者向け：追加費用がかからない理由

**今回追加した更新・自動表示更新・監視の仕組みは、既存の無料サービスと閲覧者のブラウザで動く処理を使っています。新しい有料サービスや従量課金APIは契約していません。**

2026年10月22日時点の実装・設定と、GitHub公式の料金条件に基づく説明です。

| 仕組み | 追加利用料 | 費用が増えない理由 |
| --- | --- | --- |
| テキストからJSONへの変換 | 0円 | 無料のNode.jsの標準機能で変換します。AI・翻訳・有料APIは使いません。 |
| 入力チェック・表示テスト・公開処理 | 0円 | 公開リポジトリで、無料対象の標準GitHub Actions実行環境を使います。 |
| サイトの配信 | 0円 | 既存のGitHub Pagesを継続使用します。公開リポジトリではGitHub Freeでも利用できます。 |
| 閲覧中の画面の自動更新 | 0円 | 閲覧者のブラウザが60秒ごとにサイトのデータを取得します。毎分GitHub Actionsを実行したり、有料の常駐サーバーを使ったりする仕組みではありません。 |
| 毎週の監視・監視の停止予防 | 0円 | 同じ無料対象の標準GitHub Actionsで実行します。有料の外部監視サービスは使いません。 |
| 警告の通知 | 0円 | GitHubのIssueと既存の通知機能を使います。有料のメール配信サービスや翻訳APIは使いません。 |

### 無料で使うための条件

- 現在の公開リポジトリと、標準のGitHub Actions実行環境を維持します。
- GitHubの保存容量・通信量などの利用制限の範囲で運用します。「無制限に無料」という意味ではありません。
- 有料の大型実行環境、有料API、有料の外部サービスなどを今後追加する場合は、別途費用の確認が必要です。
- GitHub側の料金条件が変更された場合は、その時点の条件を確認します。

### 「追加費用0円」に含まれないもの

- 以前から使用している独自ドメインの更新料
- 更新者・閲覧者が通常使用するインターネット回線の料金
- 将来、技術担当者に調査・修正を依頼する場合の作業費

**今回の仕組みを動かすサービス利用料と、人に対応を依頼する作業費は別です。脆弱性の警告が届いた場合に、その修正作業まで自動的に無料になるという意味ではありません。**

### 公式の根拠

- [GitHub Actionsの料金説明](https://docs.github.com/en/billing/concepts/product-billing/github-actions)：公開リポジトリで標準のGitHubホスト実行環境を使う場合、実行時間は無料です。保存容量などには別途条件があります。
- [GitHub Pagesの利用条件](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)：公開リポジトリではGitHub Freeでも利用できます。

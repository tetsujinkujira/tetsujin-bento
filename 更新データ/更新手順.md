# 鉄人サイトの更新手順

更新者は、このフォルダの3つのテキストを編集します。カンマ、引用符、JSONの知識は不要です。

| 更新したい内容 | 編集するファイル | 変えるところ |
| --- | --- | --- |
| お知らせ | [お知らせ.txt](お知らせ.txt) | 日付・件名・本文 |
| 月ごとの日替わり | [日替わり.txt](日替わり.txt) | 年・月・各曜日の料理・備考 |
| お弁当・サイド・大盛りの価格 | [商品価格.txt](商品価格.txt) | 商品名の右側の数字 |

## 1. 編集する

お知らせは最新の1件を入れ替えます。日付は半角の「年-月-日」、本文は「本文：」の次の行から書きます。本文の改行や「引用符」、カンマはそのまま使えます。

```text
日付：2026-10-22
件名：営業時間のお知らせ
本文：
いつもご利用ありがとうございます。
ここにお知らせの文章を記入します。
```

日替わりは年と月を更新し、各曜日の料理名を1行ずつ書きます。「【月曜日】」〜「【土曜日】」の見出しを残してください。不要になった料理の行は削除できます。全料理を削除する場合は備考を記入します。

```text
【月曜日】
鶏の唐揚げ
ポテトサラダ

【土曜日】
備考：当日、お電話にてご確認ください。
```

商品名・よみがなは通常変更しません。日替わりの価格は「商品価格.txt」の「桜桃」で変更します。日替わり欄と商品一覧に同時に反映されます。

価格は商品名の右の数字だけ変更します。「：」と商品名を残し、行を削除しないでください。カンマや「円」は不要です。全角数字にも対応します。

```text
グレート竜田：1000
桜桃：750
ライス大盛り：100
```

商品追加・削除・改名、写真、配達条件などを変えたい場合は技術担当者に依頼してください。

## 2. 保存して送信する

手元のファイルを編集している方は、最初にGitHubのmainの最新版を取得し、この「更新データ」フォルダがあることを確認してください。古いCMS試用ブランチでは更新しません。UTF-8のテキストとして保存し、これまでの方法で変更をGitHubに送信（commit / push）します。JSONを自分で作ったり送ったりする必要はありません。

ブラウザだけで編集する場合：

1. [GitHubの更新データフォルダ](https://github.com/tetsujinkujira/tetsujin-bento/tree/main/更新データ)を開き、更新権限のあるアカウントでログインします。
2. 対象のテキストを開き、鉛筆マーク「Edit this file」で編集します。
3. 保存前に「Preview」や差分を見て、価格・日付・料理の内容を確認します。
4. 「Commit changes…」を押し、変更の説明（例：「11月の日替わりを更新」）を記入します。
5. 直接mainへ保存する選択肢がある場合はそれを選び、「Commit changes」で確定します。ブランチで保存した場合は、mainに取り込むまで公開されません。

複数ファイルを同時に公開したい場合は、手元でまとめて編集して1回でcommit / pushしてください。ブラウザで1ファイルずつmainに保存すると、その都度公開処理が始まります。

## 3. 公開結果を確認する

1. [公開処理の一覧](https://github.com/tetsujinkujira/tetsujin-bento/actions/workflows/deploy.yml)を開き、自分の変更に対応する実行を開きます。
2. 「build-and-test」と「deploy」の両方が緑の成功になるまで待ちます。通常は数分程度です。
3. [公開サイト](https://www.tetsujin-kujira.com/)を開き、変更したお知らせ・日替わり・価格を確認します。古い表示のままなら再読み込みして少し待ちます。

保存 → テキストの入力チェック → JSON生成 → 表示・機能テスト → 公開の順に動きます。

## 赤い失敗表示になったら

以前の公開内容が残ります。JSONを修正する必要はありません。

1. 失敗した実行を開き、「build-and-test」の「Build」を開きます。
2. 「お知らせ.txt」「日替わり.txt」「商品価格.txt」と書かれた日本語のエラーを探します。
3. そのテキストを直し、もう一度保存・送信します。
4. 成功と公開内容を確認します。

例：「【土曜日】がありません」なら見出しを戻します。「桜桃がありません」なら価格行を戻します。理由がわからない場合は、失敗した実行のURLを技術担当者に渡してください。赤表示を無視したまま更新完了にしないでください。

数字として正しい「7500」などの誤記は機械だけでは判断できません。保存前の内容確認は必要です。

## 費用と監視

現在の公開GitHubリポジトリ・標準GitHub Actions・GitHub Pagesを使用し、この仕組みの追加利用料は0円です。AIや有料APIを使用しません。

毎週火曜10:23（日本時間）のセキュリティ監視、対応が必要な場合だけの日本語通知、停止予防は継続します。監視は更新・公開を行いません。テスト通知も送りません。

技術担当者向け：`npm run validate:content` は入力確認、`npm test` は変換・ビルド・画面テストです。公開用JSONは `dist/data/` に生成されます。`content/templates/` と旧 `public/data/news.json`・`daily.json` は通常の更新対象ではありません。
